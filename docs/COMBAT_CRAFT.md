# 战斗动作与桌面观赛 0.2

## 实施目标

先完成有用且可读的基础动作，再让AI组织招式与战术。不是给任意乱挥叠上火花。维持一个Stick & Steel物理身体，不引入第二引擎，不把场景装饰或手机适配当作进度。

## 已完成代码

五种不同攻击线和手部/躯干协同目标；分阶段动作承诺、额外付费的早期取消与恢复；高/内/外/低持械架势；付费后撤步与冲刺共享冷却；从JSON到实际身体的降低姿态；真实动作元数据回放；终局1.5秒物理收尾不改赛果。平台选择不了进攻或防守时机，由策略配置决定。

桌面设计/观战分离、稳定双人镜头、全景/全屏/纯净模式、实际剑尖轨迹开关、招式与阶段标识、接触时间点复盘。动作实验室可在同一引擎中逐招对照，不冒充AI作品。背景看台/旗帜在原场地外，无隐藏墙。移除手机布局与手机验收。

## 实际调试，不掩盖失败

最初的目标轨迹计时比实际身体响应快，导致部分接触滞后。调整了共享目标过滤、有限力矩和武器转向跟随，保留原关节限制与动态接触。判定明确允许承诺攻击的残余随动，而不是按动画阶段偷偷填伤害。

最初低位架势不在低斩攻击线上，经过真实身体目标对照后修正。当前固定夹距对照中，低位姿态可避开该低斩，而高位架势被击中；未产生兵器交锋事件时只能叫改变暴露/避开，不能叫格挡成功。所有架势都不是全方向无敌，未证明在所有距离和时机都有效。

初轮新增测试3项因端点浮点舍入量约1e-16失败，改为1e-12数值容差，不删除阶段/轨迹断言；重跑43/43通过。6项原始核心物理测试与构建通过。原测试源与原vendor均未改动。

## 可重跑证据

```sh
npm test
npm run test:upstream
npm run test:combat
npm run build
```

outputs/craft-validation/ 保存35组实际物理对照（5剑招×7防守输入）、真实剑尖位置、生命/事件、完整换位开发对局和源摘要。tests/helpers中的位移只用于初始化试验夹具，开始后不移动刚体制造命中。

本地固定环境Linux / Node22.16.0，两场开发对局分别24.0667秒、9.1333秒产生实际终局，墙钟约3.00秒、1.40秒（含初始化/记录/物理收尾），不是网页FPS。第一场中前压使用横斩/反斩/劈斩/低斩/刺击与取消，反击样例还使用后撤、降低姿态和重新拾取，呈现不同指令和状态；具体原始计数以证据为准，不把动作次数当作智能评分，也不强求每场必须使用每一招。

## 尚未等于完成的目标

本地浏览器导航仍被环境策略阻止，未绕过；远端普通CI浏览器检查与截图在代码发布后单独记录。自动用例证明动作执行与具体攻防关系，不等于整场观赏性已获用户认可。

没有盾牌、任意关节轨迹、现代动作捕捉美术、独立AI设计验收或正式总榜。原始游戏的跨浏览器/Node差异、接触顺序/同时失能和更广对手平衡仍待独立审计。现有固定场景对照不证明真实剑术准确性或普适克制关系。
