# 架构

## 三层职责

1. `.engine/stick-steel/lib/duel/physics.ts`及rig：固定上游和显式补丁生成，Rapier120Hz；身体执行、命名招式阶段及接触伤害属于平台。
2. `src/arena/runtime.ts`步骤执行：按时长、接受反馈、超时产生move、guard/aim和一次性命令；aim_to只改变待机/格挡，不覆盖已承诺攻击或移动刚体。
3. 同文件条件选择：从只读公开观察计算特征，按优先级、冷却及有限历史选招式，不读取对手内部资源或未来动作。

`src/engine/adapter.ts`是受信边界：先取得双方同tick观察并生成两个动作，双方都校验后再写入任何一边输入。外部控制独立于online标志。`src/arena/match.ts`每6物理步调用双方策略，每4步保存实际姿态。

## 定型动作与身体

src/arena/choreography.ts是公开纯动作数据/采样器。prepare-engine依序应用external-control、combat-craft、combat-body补丁，再复制同一采样器进引擎。补丁核对来源字节与唯一替换。手臂、剑、躯干仍是原Rapier动态刚体，跟随速度及有限力矩边界公开在补丁中。

命名动作在物理tick推进，有起手、出剑、收势。改aim/举剑不能重写承诺轨迹；feint仅取消早期起手并付出代价与收势。纯待机目标摇动无兵器伤害资格；已承诺攻击的残余随动仍按实际接触结算，不按名字扣血。

原游戏自动朝向、平衡、握持和动作执行辅助公开对称。平台不替AI决定正确格挡线、进攻或撤步时机。只开放单手剑和练习场；接触处理顺序、同tick双重失能等公平性边界仍待专门审计。

## 桌面观赛与回放

Stage复用原avatar、weapon-view、effects和audio，采用基于双方中点的SpectatorCamera，不偏向红方跟拍。桌面观赛是唯一UI目标，工作台与比赛分离，纯净观战只隐藏UI。看台无碰撞，原场地几何不变，没有手机/触控功能或手机验收。

浏览器按墙钟调度固定步进，落后时显示积压，不丢物理步。隐藏或用户暂停属于本机开发暂停，不是严格实时服务器；CLI尽快计算不等墙钟。

回放使用单独展示世界，通过快照消费者放置历史姿态，绝不再运行裁判；不能把回放世界作为比赛继续模拟。姿态30Hz采样，不保存/恢复全部约束。

Match竞争档案在终局冻结。postrollStep只生成最多180步presentationFrames，不执行策略、不追加竞争帧或改Outcome。观看端渲染物理落地，不当作新的比赛。MotionLab直接发公开动作做开发对照，按公开动作时间精确定格物理tick，不进入参赛计时或排名，预设的是输入而非命中和胜负。

## 冻结、来源与边界

prepare-engine校验上游原文件，生成带补丁副本，对动作、规则、适配器、执行器、Match、依赖锁及补丁建立摘要。网页生成只读设计快照；CLI会话和冻结副本另有配置SHA-256。文档、装饰、样例不属于引擎身份。

本地elapsed和文件系统不是防篡改计时，仅解释有界JSON，不执行参赛者代码，不承诺云端安全沙箱。模型只在赛前设计，不在比赛中调用API。

仅一个Stick & Steel物理内核，不移植旧MuJoCo或自研轻量内核。vendor与其测试原样保存；未使用的商店/联机模块不进入新入口依赖图，不连接上游Genex生产服务。
